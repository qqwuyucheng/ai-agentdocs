# AGENTS.md · 排障与 Bug 修复协议（Debugging）

> 适用场景：报错、行为异常、线上问题、偶现缺陷、性能劣化。
> 用法：复制到目标项目根目录改名为 `AGENTS.md`，并叠加「维护协议」第 0 节。

## 1. 触发与退出条件

**触发**：出现与预期不符的行为；或用户贴了报错 / 截图 / 日志。

**退出（DoD）**：
- 能**稳定复现**原始问题（有复现步骤或失败测试）。
- 定位到**根因**并有证据（日志、断点、二分结果），不是「改完好像好了」。
- 修复后原问题消失，且**新增一条回归测试**防止复发。
- 相关功能的既有测试全绿。

## 2. 硬性规则

1. **不能复现就不修**：先要到复现条件（输入、环境、版本、数据）。拒绝「先猜着改」。
2. **复现最小化**：把触发条件缩到最小输入/最短链路，再开始定位。
3. **一次只改一个变量**：每次实验只动一处，记录「改了什么 → 结果如何」。
4. **修根因不修症状**：禁止用吞异常、加 `try-catch`、加 sleep、加重试来让报错消失。
5. **同一思路连续失败 3 次即停手**：换假设、换工具或问用户，不要重复空转。
6. **修复即回归**：每修一个 bug，必须补一条能复现该 bug 的测试。

## 3. 标准流程

1. **收集**：完整报错、堆栈、版本、环境、最近变更（`git log`、依赖变更）。
2. **复现**：写成可重复执行的步骤或失败测试。
3. **缩小**：二分注释 / 二分提交 / 最小输入，锁定范围。
4. **定位根因**：读代码 + 加日志 + 断点，找到「为什么会这样」。
5. **修**：最小改动修复根因。
6. **验**：回归测试 + 原场景复测 + 相邻功能抽查。

## 4. 交付前自检

```
<复现命令>          # 修复前失败，修复后通过
<全量测试命令>       # 全绿
git diff             # 改动仅限根因相关，无夹带
```

## 5. 反模式

- 没复现就开始改代码。
- 用 try-catch / 默认值 / 重试把错误掩盖掉。
- 一次改多个地方，无法判断哪个生效。
- 修好了但没加回归测试，下次同样复发。
- 忽略「最近改了什么」，从零排查。
