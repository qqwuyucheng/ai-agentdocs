# AGENTS.md · 测试与交付验收协议（Delivery）

> 适用场景：功能完工要交付、要上线、要给他人验收、要发版。
> 用法：复制到目标项目根目录改名为 `AGENTS.md`，并叠加「维护协议」第 0 节。

## 1. 触发与退出条件

**触发**：用户说「做完了吗」「可以交付了吗」「上线」；或一次需求进入收尾。

**退出（DoD）**：
- 一条命令跑完全部自检且全绿（lint / typecheck / test / build）。
- 关键路径 + 边界场景已手动验证（空值 / 超大 / 权限 / 并发 / 断网）。
- 交付说明写完：改了什么、怎么验证、已知限制、回滚方式。

## 2. 硬性规则

1. **完成定义包含可验证**：不能只靠「写好了」判断完成，必须有可复现的验证证据。
2. **自检命令集中唯一一处**：写在 `AGENTS.md`「交付前自检」章节，任何地方不再重复散写。
3. **交付前必须全量跑**：不允许只跑改动相关的部分测试。
4. **手动验证边界**：至少覆盖空输入、极值、无权限、重复提交。
5. **不交付半成品**：注释掉的代码、调试日志、临时开关、`TODO` 不得进入交付。
6. **交付说明必含回滚方式**：出问题时怎么快速退回上一版本。

## 3. 标准流程

1. **自检**：跑全量命令，记录输出。
2. **手动验收**：按验收标准逐条点击/调用验证，留截图或日志。
3. **清理**：移除调试代码、临时文件、无用开关。
4. **写说明**：变更点 / 验证方式 / 已知限制 / 回滚步骤。
5. **提交**：一次提交只对应一个可描述的变更。
6. **复述给用户**：用一句话总结结果，并给出证据位置。

## 4. 交付前自检

```
<lint 命令>
<typecheck 命令>
<test 命令>
<build 命令>
<启动/冒烟命令>
git status            # 无未预期文件、无调试残留
```

## 5. 反模式

- 跳过 CI，「本地看着没问题」。
- 只测 happy path，边界全漏。
- 交付不说怎么验证，让对方自己猜。
- 把未验证的猜测当结论汇报。
- 一次提交混杂多个不相关改动，出问题无法回滚。
