# AGENTS.md · 重构与技术债协议（Refactoring）

> 适用场景：代码腐化、要换架构、要拆分模块、能力不变但要变干净。
> 用法：复制到目标项目根目录改名为 `AGENTS.md`，并叠加「维护协议」第 0 节。

## 1. 触发与退出条件

**触发**：新增功能越来越慢；或用户明确说「不改功能，只优化结构」。

**退出（DoD）**：
- **对外行为完全不变**：所有原有测试通过，关键路径手动验证一致。
- 每一步重构都可独立编译、独立测试、可回滚。
- 公共 API 兼容（或破坏性变更已获用户书面确认）。
- 有前后对比：测试数量、构建耗时、复杂度变化。

## 2. 硬性规则

1. **行为不变是唯一目标**：重构中不允许顺手加功能、改文案、改错误码。
2. **没测试先补测试**：重构前先为待改区域补「特征测试」（characterization test），锁住现有行为。
3. **小步前进**：一次只用一个重构手法（提取函数 / 改名 / 内联 / 搬移），一次一提交。
4. **禁止重构 + 改功能混在同一提交**。
5. **破坏性变更必须确认**：改公共接口签名、数据格式、URL 时，先说明影响面并获确认。
6. **不扩大范围**：只重构目标模块，不顺手格式化全仓。

## 3. 标准流程

1. **定范围与目标**：改哪个模块、解决什么具体问题（如「循环依赖」「重复逻辑 3 处」）。
2. **补特征测试**：覆盖当前行为，跑绿基线。
3. **逐步重构**：每一步后跑测试，绿了再继续。
4. **对比验证**：新旧实现同一输入产出相同输出（可用快照测试）。
5. **更新文档**：同步更新架构说明与 `AGENTS.md` 中的结构约定。

## 4. 交付前自检

```
<全量测试命令>        # 全绿，且测试数量未减少
<build 命令>          # 构建耗时无异常劣化
git diff --stat       # 改动集中在目标模块
```

## 5. 反模式

- 大爆炸式重写，长期不可运行。
- 无测试直接重构，靠肉眼判断「应该没变」。
- 重构夹带新功能，出问题无法归因。
- 顺手全局格式化，制造巨型 diff。
