# AGENTS.md · 新项目启动协议（Greenfield）

> 适用场景：空仓库、只有一句话想法、或只有一个 README，要从零跑通第一版。
> 用法：复制到目标项目根目录改名为 `AGENTS.md`，并在顶部叠加「维护协议」第 0 节。

## 1. 触发与退出条件

**触发**：仓库没有任何可运行代码；或用户说「从零做一个 X」。

**退出（DoD）**：
- `git clone` → 安装依赖 → **一条命令启动** → **一条命令测试通过**。
- 主流程 happy path 能跑通，且有一个可演示的最小闭环。
- 有 `.gitignore`、`.env.example`、锁文件（lockfile）、一页启动说明。
- 有一条记录技术选型理由的 ADR。

## 2. 硬性规则

1. **选型未确认不动手**：语言、框架、数据库、部署方式，必须先和用户确认或给出 2～3 个方案及取舍后再写代码。
2. **第一个里程碑是最小闭环，不是完整功能**：先跑通「输入 → 处理 → 输出」一条链，再铺其他能力。
3. **目录按领域分层，禁止 controller/service/utils 大杂烩**。一个功能一个目录，内部再分模块。
4. **依赖锁版本**：提交 lockfile；引入新依赖前说明用途，不引入未验证的库。
5. **密钥零硬编码**：一律走环境变量，`.env` 进 `.gitignore`，同时提供 `.env.example`。
6. **禁止为未来铺路**：不建用不到的抽象层、不预生成空目录、不写「以后可能会用」的接口。

## 3. 标准流程

1. **三问收敛**：目标用户是谁 / 核心流程是什么 / 什么算成功。
2. **选型并留痕**：写 `docs/adr/0001-技术选型.md`，记录选了什么、为什么不选替代品。
3. **搭骨架**：目录结构 + 依赖 + 一键启动脚本（`make dev` / `npm run dev` / 等价命令）。
4. **打通最小闭环**：只做 happy path，先不处理异常分支。
5. **建质量基线**：接入 lint + typecheck + test + build，全部一条命令可跑。
6. **写本项目的 AGENTS.md**：用本模板做基线，写入真实的自检命令。

## 4. 交付前自检

```
# 替换为项目真实命令，全部必须绿
<install 命令>
<lint 命令>
<typecheck 命令>
<test 命令>
<build 命令>
<启动命令>   # 手动确认能起、能访问
```

## 5. 反模式

- 一上来写抽象层、DI 容器、插件系统。
- 先把完整目录树全建好，再逐个填空。
- 一次性写完所有功能，中途不可运行、不可验证。
- 复制网上模板但不理解其中配置。
- 把 API Key 写进代码或提交 `.env`。
