# AGENTS.md · 多 Agent 协作协议（Orchestration）

> 适用场景：一个主 Agent 拆任务、多个子 Agent 并行执行；或人机混合、多轮长任务。
> 用法：复制到目标项目根目录改名为 `AGENTS.md`，并叠加「维护协议」第 0 节。

## 1. 触发与退出条件

**触发**：任务可拆成 2 个以上相对独立的子任务；或单次上下文装不下全部工作。

**退出（DoD）**：
- 所有子任务产出已被主 Agent**核验**（看真实改动，不信自述）。
- 无文件冲突、无重复劳动、无半成品遗留。
- 主 Agent 输出一份收尾说明：做了什么、验证结果、剩余风险。

## 2. 硬性规则

1. **决策不下放**：主 Agent 负责拆解、判断、合并；子 Agent 只执行边界清晰的任务，不替主 Agent做取舍。
2. **交接必须完整**，缺一不可：
   - 任务目标与完成定义
   - 已确认的事实与结论（不要重复调研）
   - 涉及文件路径、函数名、行号
   - 禁止触碰的文件/目录
   - 验收方式与自检命令
3. **并行任务不得改同一文件**；有交集就串行，由主 Agent统一合并。
4. **不转包理解**：禁止对子 Agent 说「根据你的发现去修」。主 Agent 必须先形成具体方案（改哪个文件哪一行）再下达。
5. **返回必核验**：子 Agent 报告完成后，主 Agent 必须读取真实 diff / 运行测试，确认与描述一致。
6. **压缩前留 handoff**：上下文即将压缩或切换前，写清「目标 / 已确定结论 / 未完成项 / 下一步」。

## 3. 标准流程

1. **拆**：按「可独立验证」为边界切分子任务，标注依赖关系。
2. **派**：每个子任务写独立、自包含的 brief（假设它看不到本次对话）。
3. **并行**：无依赖的同时跑；有依赖的串行。
4. **收**：主 Agent 汇总，解决冲突，跑一次全量自检。
5. **验**：核对每个子任务 DoD，未达标退回重做而不是自行补丁。

## 4. 交付前自检

```
git diff --stat              # 确认改动范围符合预期，无越界文件
<全量测试命令>               # 合并后必须整体再跑一次
```

- 每个子任务是否有明确的验收证据（测试输出 / diff / 截图）？
- 是否存在两个 Agent 对同一处做了冲突修改？

## 5. 反模式

- 让子 Agent「自己判断怎么改」。
- 多个 Agent 同时改同一个文件。
- 重复让不同 Agent 调研同一件事，浪费上下文。
- 子 Agent 说「已完成」就直接采信。
- 长任务中途不记录 handoff，压缩后丢失关键结论。
